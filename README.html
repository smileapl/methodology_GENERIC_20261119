外挂服务器逆向还原 · 通用版说明

本仓库讲的是把某个外挂套件（游戏辅助工具）背后的私有服务端重新造出来：授权/卡密、配置与偏移表下发、版本更新、心跳与远程指令、卡盟发卡对接。

主体是外挂自己的后台，不是游戏服务器，也不是外挂客户端本身。这个区分是全文第一条纪律，搞错主体，后面所有判据都会指向错误的对象。

二、这版做了哪些结构调整

维度上一版（游戏服务端重建）本版（外挂服务器还原）为什么换
还原对象目标游戏自己的业务服外挂套件自己的后台前者的代码与协议属于游戏；后者的"能不能用"由外挂服务端决定
核心链路登录 → 进场景 → 业务请求 → 状态迁移卡密 → token → 拉配置 → 注入 → 心跳扣时 → 到期/踢人交付物从"能玩"变成"能用、能计费、能停"
协议建模单位帧 / 方法号 / 容器路径号端点 / 字段 / 卡密记录外挂后台几乎全是 HTTP(S) 或轻量长连，端点才是自然单位
关键数据属性、容器、实体 guidCFG_BLOB、OFFSETS_TABLE、剩余时间外挂的"弹药"是偏移表，不是物品数据
风控视角识别官方反作弊机制识别客户端上报面与封禁下发形态目标是让自建服不被上游一套判定带走
工程重心状态机与幂等账本一致性 + 配置同代 + 卡盟对账外挂后台的失败代价是钱

三、术语改名表（先记这三行）

本文用词指什么不要理解成
服务端外挂自己的后台（授权/配置/更新/心跳/卡盟）游戏服务器
客户端外挂本体：loader + 注入模块 + UI + 网络层游戏客户端
宿主被辅助的游戏进程外挂进程

其余占位常量（TARGET、CHEAT_CORE、LICENSE_KEY、HWID、API_BASE、CFG_BLOB、OFFSETS_TABLE、SIG_KEY、SESSION_TOKEN、CARDMALL_API、MSG_* 等）在主文档「阅读约定」一节有完整表。

四、建议阅读顺序

  1. 本文件 + NOTICE.md —— 10 分钟，确认"这是方法论而非教程/工具包"。
  2. 主文档「第 0 章 总纲」 —— 三条前提的实证动作（断网 / 黑洞 / 空 200），10 分钟能做完，不做完别往下读。
  3. GENERIC_CHECKLIST.md 的 P0–P11 主表 —— 建立全局节奏。
  4. 带具体问题回主文档（不要顺读 1700 行）：卡在授权看第 6 章，卡在配置看第 7 章，卡在"返回 200 但功能不亮"看第 9 章。
  5. 动手前扫 GENERIC_PITFALLS.md —— 43 条里至少一半是"不知道就白干两天"。
  6. 交付前回到主文档「第 13 章 一页速查」过验收十项。

五、这版的可验证性来自什么

  • 每条结论带标记：【判据】（可复现）/【实测】（有代次）/【反例】（骗过一次的形态）/【估算】（有前提）。
  • 每章末尾有「本章要点」，作为快速自检。
  • 需要"改一手验证"的地方都给了最小可跑代码：XOR 扫描、KDF 候选枚举、签名拼接枚举、AES-CBC 双 IV 位置试解、RC4、心跳间隔统计、回调验签。
  • 报数字的规矩写在明处：必须给分母 + Δ + 未命名占比 + 档位，只报百分比视为无效。

六、与上一版的关系

上一版三份文档（GAME_SERVER_REBUILD_GENERIC_METHODOLOGY.md / GENERIC_CHECKLIST.md / GENERIC_PITFALLS.md）的内容是一个联网游戏自有服务端的重建方法论。本版把它们整体改写为外挂服务器还原，链路、术语、数据模型、坑表、验收项全部替换；旧版仍保留在 git 历史里，可用下面的命令取回：

git log --oneline -- GAME_SERVER_REBUILD_GENERIC_METHODOLOGY.md
git show <commit>:GAME_SERVER_REBUILD_GENERIC_METHODOLOGY.md > old_methodology.md

两版可以并读：旧版讲"怎么理解一个自加密的私有协议"，本版讲"怎么把一个靠协议吃饭的生意重新跑起来"。方法层有继承，判据层几乎全不同 —— 不要混用。

七、使用边界

  • 本仓库只有文档与方法，不含可运行的攻击工具、目标地址、凭据、卡密或私有数据。
  • 文中所有编号类信息（消息号、错误码、卡密校验位、偏移字段）均标注「换目标必须重新枚举」，照抄会失败，这是刻意的。
  • 引用请注明来源仓库；转载正文请保留本文件的术语改名表与 NOTICE.md 的使用边界，否则"通用版"会退化成"看起来像教程的残缺笔记"。
